# Confirmed fixes and regressions — 2026-10-19

- Active chat shell fabricated verdicts, sources, workflow success and recent sessions; the API client called nonexistent conversation routes and fabricated results on errors. Replaced those paths with the actual verification API and evidence/terminal-state adapter. Network errors propagate; failed/withheld candidates are not displayed as verified. Node contract tests cover supported, mixed, empty evidence, withheld, failed and malformed responses.
- Authentication accepted arbitrary email/password and unsigned Google payloads locally. `AuthContext.tsx` and `AuthModal.jsx` now use real backend authentication and `/auth/me`; removed synthetic identity/Pro labels. Google button cannot manufacture success. Live HTTP accounts/history isolation and invalid-token rejection tested.
- Judge tolerated unsupported peripheral claims while releasing the entire draft. Removed that ACCEPT branch; retries then abstention apply to every remaining factual gap. Updated the old permissive test and retained separate fully-supported terminal acceptance coverage.
- Judge trusted `passed=true` even with missing independent reports. It now validates completed nonempty supported reports/evidence. ReVerifier itself requires supporting evidence as well as verdicts and complete corrected-claim coverage.
- Initial Verifier could return a supported subset without covering every submitted claim. Added ID/count/text coverage checks; missing, duplicated, unexpected and mismatched reports fail closed.
- Nonempty hosted extraction could omit source facts. Added deterministic whole-source factual backstop with collision-free claim IDs. Every added claim still goes to evidence verification.
- Live correction exposed a false off-topic rejection: formatting words and the cardinal qualifier in a request were counted as factual topics. Presentation phrases are now excluded without changing the coverage threshold; wrong-entity/relation and number-bearing company-name regressions remain enforced. Corrector guidance now prefers an affirmative evidence-backed replacement over unsupported denial.
- Memory store acknowledged sub-100-entry vector batches before durable saving. Store now saves the vector layer before acknowledging success; a reopen-and-recall regression uses the actual encoder and on-disk FAISS index.
- Memory update bypassed the store gate: a negative audit could be promoted using only a verified flag, and new_evidence was ignored. Updates now require fresh attributed evidence for promotion, retain provenance/confidence, persist vector changes and retain cache consistency; adversarial promotion and durable metadata regressions were added.
- Memory accepted unsupported states/direct verified flags without evidence. Rejects unknown/incomplete statuses and unsupported verified writes before side effects; graph also rejects partial accepted states and unreverified corrections. Negative audit records retain negative verdicts.
- Concurrent graph Memory nodes created independent persistence snapshots and could overwrite one another. Added per-event-loop serialization for the single-worker local backend; a regression exercises overlapping load/update/save operations. Cross-process writers remain outside the validated single-worker setup.
- API fallback aggregation could call mixed reports verified when the graph status was missing. It now requires every report to be positively verified.
- Current checkout had the legacy sentence Detector despite the existing upgrade branch. Ported the established upgrade while preserving current Phase 1 code and prior tests. Added explicit probabilities/provenance through the bridge. Fixed passive compound splitting and retained sentences beyond the shared decomposer cap.
- Benchmark counted all checked invariants as passed and inspected outdated guard warning text. Counts now reflect actual successes; checks recognize the explicit verification warning without requiring fabricated neural confidence.
- Combined test collection polluted `config` by importing Judge as a top-level module. The test now imports the canonical package path, preventing Verifier configuration import collisions.
- Existing Memory lifecycle fixtures used bare verified flags. Added explicit fixture evidence/provenance while preserving storage/cache/duplicate/recall/deletion assertions, alongside new adversarial rejection tests.

No dependency was added, no provider/model was substituted, original model weights and user stores were preserved, and no deployment occurred. Regression logs distinguish old fixture failures, final passes and genuine limitations.
