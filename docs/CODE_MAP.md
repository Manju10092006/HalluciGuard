# HalluciGuard implementation map

Audit date 2026-11-07. Entry commit `80769fa2689f909008b0342cd3ee1e88f4c26f28`. The source snapshot and prior user changes are in `results/research_20261106_r1/baseline`. This map describes the local implementation, including opt-in candidates introduced on this branch. It does not assert that every supported deployment configuration has been evaluated.

## Shared contracts and orchestration

`orchestration/state.py` defines `HalluciGuardState`. `orchestration/schemas.py` defines `DetectorResult`, `Evidence`, `ClaimReport`, `VerifierResult`, `JudgeResult`, `CorrectionRequest`, `CorrectionResult`, `ReverificationResult` and `MemoryResult`. `orchestration/graph.py` contains the compiled `build_verification_graph`, `run_verification`, agent nodes, routing functions, and canonical adapters. Completed reverification returns to the Judge. Failed verification routes to human escalation. Every terminal route crosses Memory. Graph tests cover canonical contracts, failures, bounded retries, correction coverage and terminal reachability. These are software checks, not factuality benchmarks.

## Research boundaries

The 22-page manuscript is a frozen editorial baseline. Historical counts remain historical. A source-backed label, a constructed card, an NLI dataset label and a software test assertion have different meanings. The current experiments retain those distinctions. Independent whole-answer human evaluation is pending. There is no validated claim that Memory improves generation or that Detector triage reduces operational cost. Baseline adapters must record their exact generator and evidence budget. Approximate published workflows must be labelled as such.
