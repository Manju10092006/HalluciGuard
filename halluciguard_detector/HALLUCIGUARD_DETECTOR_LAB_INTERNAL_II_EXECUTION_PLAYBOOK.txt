STEP 2 — THE MOST IMPORTANT THING: GET THE APPLICATION IMAGE
================================================================
Ma'am's GitHub repository is the SOURCE CODE. It is not
automatically a Docker image. You have to build the image yourself.

2a. Clone the repository (use the URL ma'am gives you in the exam;
    the one below is the OLTRS repository):

    git clone https://github.com/archanareddyse/OLTRS.git
    cd OLTRS
    dir

2b. Check the project files:

    dir pom.xml
    dir Dockerfile
    dir

    (On Bash / Git Bash / Linux, use ls instead of dir.)

2c. Build the project:

    mvn clean test package

2d. Check the generated output:

    dir target

    (On Bash / Git Bash / Linux, use ls target.)

2e. CREATE THE DOCKERFILE — ma'am's repo HAS a Dockerfile file
    but it is EMPTY (checked the repo: the file contains nothing).
    You must write the code into it yourself.

    First check what the build produced (Step 2d). For OLTRS the
    answer is already fixed — pom.xml says <packaging>war</packaging>,
    Java 8, javax.servlet 4.0.1 (Tomcat 9). So the build produces
    target/ticket-reservation.war. There is NO jar case for OLTRS.

    Open the Dockerfile in the project root and write this into it
    (PowerShell: notepad Dockerfile — then Save; the file must be
    named exactly "Dockerfile", no .txt extension):

    FROM tomcat:9.0-jdk8
    COPY target/ticket-reservation.war /usr/local/tomcat/webapps/ROOT.war
    EXPOSE 8080
    CMD ["catalina.sh", "run"]

    WHY tomcat:9.0-jdk8 and NOT tomcat:10.1-jdk17: Tomcat 10 uses
    the jakarta.* namespace. This project uses javax.servlet.*
    (Servlet 4.0, Tomcat 9). A javax WAR will NOT run on Tomcat 10.
    Java 8 in pom.xml matches the jdk8 image.

    Verify the file saved correctly:

    dir Dockerfile
    type Dockerfile

    (On Bash / Git Bash / Linux, use: cat Dockerfile.)

2f. Build your application image (replace YOUR_DOCKERHUB_USERNAME
    with your own Docker Hub username):

    docker build -t YOUR_DOCKERHUB_USERNAME/oltrs:v1 .

2g. Login and push the image to Docker Hub:

    docker login
    docker push YOUR_DOCKERHUB_USERNAME/oltrs:v1

    Example with your own Docker Hub username:

    docker build -t sogalapallimanjunathreddy/oltrs:v1 .
    docker push sogalapallimanjunathreddy/oltrs:v1

2h. Kubernetes uses this SAME image — do not build a second image
    for Kubernetes:

    sogalapallimanjunathreddy/oltrs:v1

Q2 — JENKINS SCRIPTED PIPELINE
------------------------------

Jenkins setup:
1. Open Jenkins URL provided by college (local default http://localhost:8080).
2. Verify Git, Pipeline and Email Extension plugins if needed.
3. Manage Jenkins > Tools: configure JDK and Maven. Previously used
   Maven tool name was MAVEN-HOME; use the name configured there.
4. Manage Jenkins > Credentials > Global > Add Credentials.
   Kind: Username with password.
   Username: Docker Hub username.
   Password: Docker Hub access token.
   ID: dockerhub-credentials.
5. New Item > OLTRS-CICD > Pipeline.
6. Enable Build Triggers > GitHub hook trigger for GITScm polling.

Scripted Pipeline for a Linux Jenkins agent (Docker CLI and Maven
must be installed and usable by the Jenkins agent):

    node {
        def imageName = "sogalapallimanjunathreddy/oltrs:v1"

        try {
            stage('Checkout') {
                git branch: 'main',
                    url: 'https://github.com/archanareddyse/OLTRS.git'
            }

            stage('Build and Test') {
                sh 'mvn clean test package'
            }

            stage('Docker Build') {
                sh "docker build -t ${imageName} ."
            }

            stage('Docker Login and Push') {
                withCredentials([
                    usernamePassword(
                        credentialsId: 'dockerhub-credentials',
                        usernameVariable: 'DOCKER_USER',
                        passwordVariable: 'DOCKER_PASS'
                    )
                ]) {
                    sh '''
                        echo "$DOCKER_PASS" | docker login \
                        -u "$DOCKER_USER" --password-stdin
                    '''
                    sh "docker push ${imageName}"
                    sh 'docker logout'
                }
            }

            stage('Success') {
                echo 'OLTRS pipeline completed successfully'
            }

        } catch (Exception e) {
            echo "Pipeline failed: ${e}"
            // Keep emailext only if Email Extension + SMTP are configured
            emailext(
                subject: "OLTRS Build Failed: ${env.BUILD_NUMBER}",
                body: "Pipeline failed. Console: ${env.BUILD_URL}",
                to: "YOUR_EMAIL_ADDRESS"
            )
            throw e
        }
    }

If failure email is not required, remove emailext(...) and retain
catch + throw. Replace YOUR_EMAIL_ADDRESS and configure SMTP only
if the paper asks for failure email.

For a Windows Jenkins agent, use bat instead of sh, for example:

    bat 'mvn clean test package'
    bat "docker build -t IMAGE_NAME ."
    bat "docker push IMAGE_NAME"

Use secure Jenkins credential binding for Windows Docker login.
Never hardcode a Docker Hub password/token.

GitHub webhook:
- GitHub repo > Settings > Webhooks > Add webhook.
- Payload URL must be a publicly reachable Jenkins URL ending:
  /github-webhook/
- Content type: application/json.
- Choose Just the push event.
- In Jenkins job enable GitHub hook trigger for GITScm polling.
- If local Jenkins and ngrok are permitted, run:

    ngrok http 8080

Use the current HTTPS forwarding address printed by ngrok, not an
old address. localhost:8080 alone cannot receive GitHub webhooks.

Jenkins scenario answers:
1. No trigger: check webhook URL/delivery, Jenkins reachability,
   job trigger checkbox, repo and branch.
2. Maven fails: failed sh/bat command aborts pipeline; Docker stages
   are not reached. Do not swallow the error.
3. Docker auth: Jenkins Credentials + withCredentials +
   docker login --password-stdin; no hardcoded secret.
4. Inspect failure: Jenkins job > Build History > failed build >
   Console Output.
5. Failure-only email: emailext inside catch block only.

Q3 — MINIKUBE / KUBERNETES YAML FILES
-------------------------------------

Ensure Docker is running, then:

    minikube start --driver=docker
    minikube status
    kubectl cluster-info
    kubectl get nodes

Create deployment.yaml:

    notepad deployment.yaml

Paste:

    apiVersion: apps/v1
    kind: Deployment
    metadata:
      name: oltrs-deployment
    spec:
      replicas: 4
      selector:
        matchLabels:
          app: oltrs
      template:
        metadata:
          labels:
            app: oltrs
        spec:
          containers:
            - name: oltrs-container
              image: sogalapallimanjunathreddy/oltrs:v1
              ports:
                - containerPort: 8080

Create service.yaml:

    notepad service.yaml

Paste:

    apiVersion: v1
    kind: Service
    metadata:
      name: oltrs-service
    spec:
      type: NodePort
      selector:
        app: oltrs
      ports:
        - port: 8080
          targetPort: 8080
          nodePort: 30080
          protocol: TCP

The image must match the image pushed to Docker Hub.
The containerPort and targetPort must match the app's real port.
Service selector app: oltrs must match Pod label app: oltrs.
NodePort 30080 is within the default 30000–32767 range.

Apply and verify:

    kubectl apply -f deployment.yaml
    kubectl apply -f service.yaml
    kubectl get nodes
    kubectl get deployments
    kubectl get replicasets
    kubectl get pods
    kubectl get pods -o wide
    kubectl get services
    kubectl get endpoints oltrs-service
    kubectl rollout status deployment/oltrs-deployment

Scale and verify:

    kubectl scale deployment oltrs-deployment --replicas=4
    kubectl get deployment oltrs-deployment
    kubectl get pods

Access:

    minikube service oltrs-service --url

Alternative:

    kubectl port-forward service/oltrs-service 8081:8080

Open http://localhost:8081

Kubernetes troubleshooting:

    kubectl describe deployment oltrs-deployment
    kubectl describe service oltrs-service
    kubectl get pods --show-labels
    kubectl get events --sort-by=.metadata.creationTimestamp
    kubectl logs POD_NAME

Scenario answers:
1. Scale: kubectl scale deployment oltrs-deployment --replicas=4
2. Outside access: NodePort Service; check targetPort and selector.
3. Pods not running: get pods, describe pods, events, logs.
4. ENDPOINTS none: Service selector must match Pod labels; Pods ready.
5. Delete:
       kubectl delete deployment oltrs-deployment
       kubectl delete service oltrs-service
   Verify: kubectl get deployments,services

Q4 — AWS EC2 DEPLOYMENT
-----------------------

AWS Console:
1. Choose required region.
2. EC2 > Launch instance.
3. Choose required AMI and instance type.
4. Create/select key pair; download .pem.
5. Create Security Group and launch.
6. Wait for Running + status checks passed.
7. Copy Public IPv4 / Public DNS.

Security Group inbound:
- SSH TCP 22: administrator public IP /32 only.
- HTTP TCP 80: 0.0.0.0/0 if public HTTP required.
- Custom TCP 8080: 0.0.0.0/0 only if directly exposing app on 8080.

From Windows PowerShell, move to key folder and connect:

    cd C:\Users\YOUR_WINDOWS_USERNAME\Downloads
    ssh -i "your-key.pem" ubuntu@YOUR_EC2_PUBLIC_IP

For Git Bash / Linux, if required:

    chmod 400 your-key.pem
    ssh -i "your-key.pem" ubuntu@YOUR_EC2_PUBLIC_IP

Inside Ubuntu:

    sudo apt update
    sudo apt install -y git docker.io maven
    sudo systemctl start docker
    sudo systemctl enable docker
    sudo systemctl status docker
    sudo usermod -aG docker ubuntu

Log out and reconnect for group change, or use sudo for Docker.
Check Java version against the project's Java 8 requirement:

    java -version
    mvn -version
    docker --version
    git --version

Clone and build:

    git clone https://github.com/archanareddyse/OLTRS.git
    cd OLTRS
    mvn clean test package
    ls target

Create Dockerfile:

    nano Dockerfile

Paste:

    FROM tomcat:9.0-jdk8
    COPY target/ticket-reservation.war /usr/local/tomcat/webapps/ROOT.war
    EXPOSE 8080
    CMD ["catalina.sh", "run"]

Save nano: Ctrl+O, Enter, Ctrl+X.

Build/run/verify:

    sudo docker build -t oltrs-app:v1 .
    sudo docker run -d --name oltrs-container -p 8080:8080 oltrs-app:v1
    sudo docker ps
    sudo docker logs oltrs-container
    sudo docker inspect oltrs-container

Browser:

    http://YOUR_EC2_PUBLIC_IP:8080

Allow inbound TCP 8080 in Security Group for direct access.

AWS scenarios:
1. SSH failure: verify instance, IP, Ubuntu username, key pair,
   .pem permissions, inbound TCP 22 from admin IP, routes / ACL.
2. App inaccessible: verify Docker port mapping, app listening port,
   Security Group, network ACL and OS firewall.
3. No Public IPv4: associate Elastic IP or configure public subnet,
   Internet Gateway route and public IPv4 assignment.
4. Persist data: EBS volume, mount it, store app/container data there;
   use persistent Docker volume or bind mount backed by EBS.
5. HTTP public / SSH admin-only: TCP 80 public; TCP 22 admin IP only.
