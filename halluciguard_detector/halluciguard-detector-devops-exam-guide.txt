STEP 0 — BEFORE YOU ENTER THE LAB: THE 4 WORKFLOWS (MEMORISE)
================================================================

1. Docker Compose
   Write docker-compose.yml -> docker compose up -d -> verify containers.

2. Jenkins
   Configure repository -> write Scripted Pipeline -> Maven build ->
   Docker build -> Docker Hub push -> webhook.

3. Minikube
   Start cluster -> create Deployment -> create NodePort Service ->
   scale to four -> access application.

4. AWS EC2
   Launch instance -> configure Security Group -> SSH -> clone
   repository -> build and run application -> access public IP.

================================================================
STEP 2 — THE MOST IMPORTANT THING: GET THE APPLICATION IMAGE
================================================================
Ma'am's GitHub repository is the SOURCE CODE. It is not
automatically a Docker image. You have to build the image yourself.

2a. Clone the repository (use the URL ma'am gives you in the exam;
    the one below is the OLTRS repository):

    git clone https://github.com/archanareddyse/OLTRS.git
    cd OLTRS
    dir

2b. Check the project files:

    dir pom.xml
    dir Dockerfile
    dir

    (On Bash / Git Bash / Linux, use ls instead of dir.)

2c. Build the project:

    mvn clean test package

2d. Check the generated output:

    dir target

    (On Bash / Git Bash / Linux, use ls target.)

2e. Create a Dockerfile in the project folder, according to the
    ACTUAL project output. If it produces a WAR file and uses
    Tomcat, the Dockerfile is:

    FROM tomcat:10.1-jdk17
    COPY target/*.war /usr/local/tomcat/webapps/ROOT.war
    EXPOSE 8080
    CMD ["catalina.sh", "run"]

2f. Build your application image (replace YOUR_DOCKERHUB_USERNAME
    with your own Docker Hub username):

    docker build -t YOUR_DOCKERHUB_USERNAME/oltrs:v1 .

2g. Login and push the image to Docker Hub:

    docker login
    docker push YOUR_DOCKERHUB_USERNAME/oltrs:v1

    Example with your own Docker Hub username:

    docker build -t sogalapallimanjunathreddy/oltrs:v1 .
    docker push sogalapallimanjunathreddy/oltrs:v1

2h. Kubernetes uses this SAME image — do not build a second image
    for Kubernetes:

    sogalapallimanjunathreddy/oltrs:v1

================================================================
STEP 6 — Q4: AWS EC2 (LAUNCH, SSH, BUILD, RUN, ACCESS)
================================================================

6a. Launch the instance, then configure the Security Group
    (allow ports 22, 80 and 8080 — see Step 7).

6b. SSH into the instance:

    ssh -i "your-key.pem" ubuntu@YOUR_PUBLIC_IP

6c. Inside Ubuntu, install what you need:

    sudo apt update
    sudo apt install docker.io git maven -y
    sudo systemctl start docker
    sudo systemctl enable docker
    sudo usermod -aG docker ubuntu

6d. Reconnect (log out and SSH in again so the docker group
    applies), then clone, build and run:

    git clone https://github.com/archanareddyse/OLTRS.git
    cd OLTRS
    mvn clean test package
    docker build -t oltrs-app:v1 .
    docker run -d --name oltrs-container -p 8080:8080 oltrs-app:v1
    docker ps
    docker logs oltrs-container

6e. Access the application in a browser:

    http://YOUR_PUBLIC_IP:8080

    Remember to allow the required application port in the EC2
    Security Group, or the page will not load.


================================================================
STEP 7 — FIVE THINGS YOU MUST NOT FORGET IN THE EXAM
================================================================

1. Docker Compose: use mysql as the database hostname inside the
   Compose network, NOT localhost.

2. Jenkins: NEVER hardcode Docker Hub passwords in the
   Jenkinsfile. Use Jenkins Credentials.

3. Jenkins webhook: GitHub must be able to reach the Jenkins
   server. A local localhost:8080 address alone will not work as
   a public webhook URL.

4. Kubernetes: the Deployment image must be the EXACT image name
   you pushed to Docker Hub. Pod labels must match the Service
   selector.

5. AWS: a running application is NOT automatically publicly
   accessible. Check port mapping AND Security Group inbound rules.
